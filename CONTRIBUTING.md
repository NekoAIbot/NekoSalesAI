# Contributing to NekoSalesAI

Welcome to the NekoSalesAI project.

This document defines the engineering standards, development philosophy, and coding rules that every contributor—including AI coding agents—must follow.

---

# Mission

Build the world's best AI Sales Employee.

Every improvement should move the project closer to becoming a production-ready autonomous AI platform capable of helping businesses acquire, engage, nurture, and convert customers.

---

# Core Engineering Principles

Every change must be:

- Production-ready
- Realistic
- Maintainable
- Modular
- Scalable
- Secure
- Well-tested
- Well-documented

Never sacrifice long-term quality for short-term speed.

---

# Development Rules

## 1. Never Break Existing Functionality

Before changing existing code:

- Understand how it works.
- Preserve existing behavior unless intentionally improving it.
- Avoid unnecessary rewrites.
- Extend instead of replacing whenever possible.

---

## 2. Think Before Coding

Every implementation should begin with careful analysis.

Understand:

- the problem,
- existing architecture,
- downstream effects,
- future scalability.

Avoid writing code that introduces technical debt.

---

## 3. Keep Architecture Clean

Follow existing project structure.

Do not create duplicate systems.

Do not introduce unnecessary abstractions.

Keep modules cohesive and responsibilities clearly separated.

---

## 4. Production Quality Only

Every feature should be implemented as if it will immediately serve real customers.

Avoid:

- placeholder logic
- fake implementations
- temporary hacks
- unfinished code
- "TODO" features for completed work

---

## 5. Testing

Every completed feature must be tested.

Testing should include:

- syntax validation
- imports
- runtime validation
- API validation
- database validation
- integration testing
- end-to-end testing where appropriate

Never knowingly leave broken code behind.

---

## 6. AI Development Philosophy

Every AI decision must be:

- explainable
- deterministic where appropriate
- realistic
- measurable
- continuously improvable

Avoid unnecessary complexity.

Prefer reliable systems over impressive-looking systems.

---

## 7. User Experience

Every interface should feel:

- modern
- professional
- calm
- responsive
- intuitive

Animations must communicate useful information.

Avoid unnecessary visual effects.

---

## 8. Shared Codebase

Maintain one shared architecture powering:

- Web
- Progressive Web App
- Android
- iOS
- Desktop

Avoid duplicating business logic across platforms.

---

## 9. Documentation

Whenever major functionality is added:

- update README if necessary
- document architecture changes
- document API changes
- explain new systems

Documentation should evolve with the codebase.

---

## 10. Continuous Improvement

Continuously look for realistic opportunities to improve:

- architecture
- AI reasoning
- automation
- performance
- scalability
- maintainability
- developer experience
- customer experience

Every improvement must provide measurable value.

---

# Git Standards

Commit frequently.

Use meaningful commit messages.

Examples:

- feat:
- fix:
- refactor:
- docs:
- perf:
- test:
- chore:

Push only tested code.

---

# Code Style

Prioritize:

- readability
- simplicity
- consistency
- explicitness

Avoid clever code that reduces maintainability.

---

# Decision Making

When multiple solutions exist:

Choose the one that is:

- simplest
- most maintainable
- production-ready
- easiest to extend
- least likely to introduce bugs

---

# Long-Term Goal

NekoSalesAI is not just another CRM.

It is an AI Sales Operating System.

Every contribution should move the project closer to becoming a fully autonomous AI Sales Employee capable of helping businesses generate revenue with minimal manual effort.
